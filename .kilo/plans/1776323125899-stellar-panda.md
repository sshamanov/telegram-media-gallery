### Task 1: Upload mode selector refinement for large files

**Purpose:** Prevent upload failures for large files by auto-adjusting upload mode based on file size and type, with user notification.

**Implementation steps:**
1. Define size limit constants in `src/lib/telegram/constants.ts` (or existing file):
   - `MAX_PHOTO_SIZE = 10 * 1024 * 1024` (10 MB)
   - `MAX_VIDEO_SIZE = 1 * 1024 * 1024 * 1024` (1 GB)
   - `MAX_AUDIO_SIZE = 200 * 1024 * 1024` (200 MB) – optional
   - `MAX_DOCUMENT_SIZE = 2 * 1024 * 1024 * 1024` (2 GB) – Telegram's generic limit
2. Modify `uploadMediaType` function in `src/lib/telegram/mtcute.ts`:
   - If mode === 'media' and file size exceeds limit for detected media type (photo/video/audio), automatically fall back to 'document' (file mode).

3. Add user notification when auto‑fallback occurs:
   - In `uploadToCurrentDialog` or `uploadQueueItems`, detect if mode was adjusted (compare original mode with actual media type).
   - Show a toast with message: "File too large for media upload; sending as document."
4. Optional: add a persistent user preference store for default upload mode (stretch goal, can be deferred).
5. Update `APPLICATION_SPEC.md` to describe the refined behavior.

### Task 3: Fix GalleryGrid accessibility warnings

**Purpose:** Resolve warnings about non‑interactive `<section>` with tabindex and event listeners.

**Implementation steps:**
1. Evaluate current role and interaction pattern:
   - The `<section>` has `role="application"`, `tabindex="0"`, `on:scroll`, `on:keydown`.
   - The a11y warning suggests the element is considered non‑interactive.
2. Possible fixes:
   - Change `role="application"` to `role="region"` (still non‑interactive) and add `aria-roledescription="scrollable gallery"`.
   - Keep `role="application"` but add `aria-hidden="false"` and `aria-live="polite"`? Not appropriate.
   - Add `<!-- svelte-ignore a11y-no-noninteractive-tabindex -->` and `<!-- svelte-ignore a11y-no-noninteractive-element-interactions -->` if we believe the current semantics are correct.
3. Consult Svelte a11y guidelines: if the element is genuinely interactive (keyboard navigation, scroll handling), we can add `role="application"` and suppress the warning with comments, but ensure screen reader users are not harmed.
4. Add `aria-label="Gallery"` (already present) and `aria-roledescription="scrollable gallery with keyboard navigation"`.
5. Ensure `tabindex="0"` is necessary for keyboard focus; if not, remove it and rely on child elements.
