# Small Improvement Iteration Plan

## Goal
Stabilize core login/navigation/mock flows first, then address the highest-impact UI issues that block real and mock testing.

## What I verified in the current code
- `src/components/auth/PhoneForm.svelte`: the 2FA password field is rendered immediately after a code is sent (`{#if $phoneCodeHash}`), not only after `signIn()` returns `'2fa_required'`.
- `src/components/auth/PhoneForm.svelte`: no form semantics or Enter-key default action exist for phone/code/password login steps.
- `src/components/auth/QRForm.svelte`: QR 2FA is already conditional and Enter works there; phone login is the inconsistent path.
- `src/stores/telegram.ts`: adapter selection is mutable globally, but the exported `telegramAdapter` constant is captured once at module init.
- `src/components/auth/PhoneForm.svelte`, `src/App.svelte`, `src/components/dialogs/DialogList.svelte`: these files call the captured `telegramAdapter` constant, so switching mock/real adapter later can leave the app using a stale adapter instance.
- `src/components/settings/SettingsPanel.svelte`: mock toggle currently exists only inside settings, which is unreachable before login.
- `src/components/dialogs/DialogList.svelte`: the `galleries` tab shows only pinned dialogs from `galleryIds`, not dialogs with `kind === 'gallery'`, so a fresh session can look empty even when gallery dialogs exist.
- `src/components/gallery/GalleryGrid.svelte`: this file is severely incomplete/broken; `npm run check` reports dozens of missing handlers/functions, and the template references many undefined symbols. This is the likeliest cause of broken gallery/viewer behavior in real testing.
- `src/lib/telegram/mock.ts`: mock login currently accepts any phone for `sendCode`, any code except `123456` for direct sign-in, and `123456` + password `password` for the 2FA path.
- `src/lib/telegram/mock.ts`: mock media JSON fetches target `samples/dialog-media/*.json`, but those files are currently absent, so mock falls back to synthetic messages.
- `package.json`: there are no UI test scripts despite `.kilo/status.md` claiming `npm run test:ui` and `npm run test:visual` already exist.
- `src/lib/telegram/mock-fixed.ts`: a second mock adapter exists but is unused; this is likely abandoned overlap.

## Iteration strategy
Keep this iteration small but unblock the app end-to-end:
1. make auth reliable,
2. make mock mode reachable and documented,
3. restore dialog/gallery/viewer basics,
4. add repeatable UI mock tests,
5. polish settings visuals.

## Implementation plan

### 1. Repair phone login UX and behavior
- Add explicit phone-login step state in `src/components/auth/PhoneForm.svelte`, e.g. `phone -> code -> password-required`, instead of deriving password visibility only from `$phoneCodeHash`.
- Show the 2FA input only after `telegramAdapter.signIn()` returns `'2fa_required'`.
- Wrap the phone login UI in semantic forms or add shared Enter handling so Enter triggers the current primary action:
  - phone step -> `Send Code`
  - code step -> `Submit Code`
  - 2FA step -> `Submit Password`
- Preserve button click behavior and disabled states so keyboard and pointer flows stay aligned.
- Add inline help text for the current step so the user knows whether the app expects code or password.

### 2. Make mock mode usable before login
- Stop importing/using the captured `telegramAdapter` constant in feature code; instead, read the active adapter dynamically through a store getter/helper so switching adapters actually changes runtime behavior.
- Update all auth/dialog-loading call sites to use the active adapter source consistently.
- Expose mock-mode selection on the login screen, not only in settings. Recommended default:
  - add a visible "Use mock data" toggle/button in `src/components/auth/AuthScreen.svelte` or `src/components/auth/PhoneForm.svelte`
  - keep the settings toggle for after login
- On mock enable/disable, fully reset auth/session/dialog/gallery state so the app cannot stay half-bound to the previous adapter.
- Remove references to the deleted `fix-mock.html` flow and replace them with in-app mock controls.

### 3. Document and verify mock login behavior
- Add a concise mock login note in the UI and README-level docs:
  - any phone number works
  - any code except `123456` signs in directly
  - `123456` triggers 2FA
  - mock 2FA password is `password`
- If this behavior feels too implicit, tighten it to one documented phone/code combo (for example `+1234567890` + `11111`) and make the UI show it directly.
- Prefer one deterministic path over permissive hidden behavior so tests and manual QA match.

### 4. Stabilize dialog loading and refresh behavior
- Fix the dialog list model so the Galleries tab is not empty on a fresh session:
  - either show real `kind === 'gallery'` dialogs directly, or
  - combine true gallery dialogs with pinned dialogs in a predictable way
- Review refresh/login/session transitions in `src/App.svelte` and `src/components/dialogs/DialogList.svelte` so dialog lists reload after:
  - initial reconnect
  - adapter switch
  - logout/login
  - page refresh
- Verify whether `dialogsLoaded` should reset when auth state changes or adapter changes.
- Ensure empty states distinguish between "still loading", "failed", and "actually empty".

### 5. Fix the broken gallery/viewer path first, not just cosmetics
- Treat `src/components/gallery/GalleryGrid.svelte` as the highest-priority repair item.
- Reconcile the script/template mismatch by either:
  - restoring the missing handlers from the intended implementation, or
  - temporarily simplifying the component to a smaller working version that supports open/back/filter/basic selection/viewer launch.
- Minimum success criteria for this iteration:
  - open a dialog from list
  - media items render
  - clicking/Enter on an item opens `ViewerWrapper`
  - back navigation returns to dialogs cleanly
- After repair, rerun `npm run check` and reduce the existing `GalleryGrid` error flood to zero or near-zero.

### 6. Fix settings screen regressions and cosmetics
- Increase border contrast/weight and interior padding for blocks in `src/components/settings/SettingsPanel.svelte`.
- Increase line-height / min-height / field padding where text currently clips.
- Review `SettingsScreen.svelte` container sizing and overflow so headers/labels do not get cut off.
- Investigate the lingering "Settings" label after leaving settings:
  - verify route transition cleanup
  - verify route state and DOM replacement when navigating back
  - if needed, simplify `routeTransition` usage until correctness is restored

### 7. Add real UI mock tests instead of relying on status notes
- Add Playwright-based local UI tests and the missing scripts in `package.json`.
- Recommended first test suite:
  - mock login happy path
  - mock login 2FA path
  - dialog lists visible after login and after refresh
  - open gallery and open viewer
  - open settings and return without stale header residue
- Add a regression test covering the exact user-reported issues where possible.
- Add a lightweight visual smoke test only after functional tests are stable.

### 8. Validate the user-reported issues against mock mode
- Run the new mock tests plus a manual mock pass to confirm whether these reproduce in mock:
  - premature 2FA field
  - Enter not submitting
  - settings clipping/border weakness
  - settings header lingering after exit
  - empty lists after refresh
  - gallery opens but viewer does not start
- If a bug does not reproduce in mock, explicitly mark it as real-adapter-only and continue with targeted real-flow inspection.

### 9. Mock cleanup after stabilization
- Decide between `src/lib/telegram/mock.ts` and `src/lib/telegram/mock-fixed.ts`; keep one implementation.
- Remove the unused mock implementation only after the active one is verified by tests.
- If `samples/dialog-media/*.json` remains intentionally absent, either generate it and use it, or simplify docs to state that synthetic fallback data is expected.

## Notes for execution

- The biggest likely root causes are the stale adapter reference pattern and the broken `GalleryGrid.svelte` implementation.
- Mock usage should become self-documenting in the login UI so no external helper HTML file is needed.
