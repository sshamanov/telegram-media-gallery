# Phase 2 Selection Mode Plan

## Goal
- Implement the first Phase 2 logical block: gallery selection mode with mobile long-press entry and desktop click-modifier support.
- Keep scope limited to selection-state management and selection UI only.
- Do not start bulk download, forward, share, clipboard, or upload-queue enhancements in this block.

## Why This Block First
- `.kilo/status.md` lists multi-select as the first pending Phase 2 task.
- `GalleryGrid.svelte`, `MediaItem.svelte`, and `MediaListRow.svelte` already expose the right event surface (`onActivate`, `onLongPress`, `selected`, `selectionMode`).
- Later Phase 2 actions all depend on a stable selected-items model and a selection header/action bar.

## Current Code Readback

### Existing strengths
- `src/components/gallery/GalleryGrid.svelte` already computes `visibleItems` from active filter and view mode.
- `src/components/gallery/MediaItem.svelte` and `src/components/gallery/MediaListRow.svelte` already render selected/selection-mode visuals and already fire `onLongPress` after 500ms for touch pointers.
- `src/stores/gallery.ts` already centralizes gallery state and is the natural ownership point for selection-mode state.

### Current gaps
- `handleItemActivate()` and `handleItemLongPress()` in `src/components/gallery/GalleryGrid.svelte` always open the viewer.
- No store state exists yet for:
  - selection mode on/off
  - selected item ids
  - anchor item for shift-range selection
- No selection header, cancel action, select-all action, or selected-count UI exists.
- No keyboard/desktop modifier handling exists in gallery item activation.
- No tests currently assert selection behavior.

## Scope For This Block

### In scope
- Add selection-mode state to `src/stores/gallery.ts`.
- Enter selection mode via 500ms touch long-press.
- Enter/toggle selection mode on desktop using modifier clicks:
  - `Ctrl`/`Meta` click toggles one item
  - `Shift` click selects a contiguous range within current filtered view
- Add gallery selection header with:
  - cancel button
  - selected count
  - select-all button
- Pass `selected` and `selectionMode` props down to grid and list items.
- Make normal click behavior conditional:
  - open viewer when not selecting
  - toggle selection when in selection mode
- Support `Escape` on gallery root to exit selection mode.

### Out of scope
- Bulk download implementation
- Forward dialog picker
- Share / clipboard actions
- Upload queue panel changes
- New adapter methods or Telegram transport changes
- Spec claims beyond selection mode unless validation passes and status/spec need narrow updates

## Implementation Plan

### 1. Extend gallery store state
Update `src/stores/gallery.ts` with selection-specific state and helpers.

Recommended additions:
- `selectionMode = writable(false)`
- `selectedMediaIds = writable<string[]>([])` or `writable<Set<string>>` if kept store-safe via cloning
- `selectionAnchorId = writable<string | null>(null)`

Recommended exported helpers:
- `enterSelectionMode(itemId?: string): void`
- `exitSelectionMode(): void`
- `toggleSelectedMedia(itemId: string): void`
- `selectOnlyMedia(itemId: string): void`
- `selectMediaRange(itemIds: string[], startId: string, endId: string): void`
- `selectAllVisibleMedia(itemIds: string[]): void`
- `isMediaSelected(itemId: string): boolean` only if useful locally; otherwise derive in component

Reset rules:
- Clear selection mode and selected ids inside `resetDialogState()`.
- Clear selection mode when dialog changes.
- Do not clear selection on filter/view toggle unless selected items are no longer in the visible set; for this block, simplest rule is to keep selection but make `Select All` operate on current `visibleItems`.

### 2. Update activation semantics in `GalleryGrid.svelte`
Replace current unconditional open behavior.

Recommended behavior:
- `handleItemLongPress(itemId)`:
  - if not already in selection mode, enter it and select `itemId`
  - optionally call `navigator.vibrate?.(50)` behind a support guard
- `handleItemActivate(itemId, event)`:
  - if selection mode is active, toggle item selection
  - else if `Shift` is pressed, enter selection mode and apply range selection from anchor
  - else if `Ctrl` or `Meta` is pressed, enter selection mode and toggle one item
  - else open viewer

Range-selection rule:
- Use `visibleItems` order as the authoritative range order, matching the active filter and view.
- If there is no anchor yet, treat first shift-click as single-item selection and set the anchor.

### 3. Add selection header/action shell in `GalleryGrid.svelte`
Swap the existing header when selection mode is active.

Minimum UI for this block:
- `Cancel` button
- selected count label (`1 selected`, `3 selected`)
- `Select All` button
- disabled action buttons shell for later phases is optional; better to omit now than present fake controls

Stable hooks to add:
- `data-testid="gallery-selection-header"`
- `data-testid="gallery-selection-count"`
- `data-testid="gallery-selection-cancel"`
- `data-testid="gallery-selection-select-all"`

### 4. Pass selection state into item components
In both grid and list render paths:
- pass `selectionMode={$selectionMode}`
- pass `selected={selectedIdSet.has(item.id)}` or equivalent derived boolean

This should light up the existing overlay/checkmark styles already present in:
- `src/components/gallery/MediaItem.svelte`
- `src/components/gallery/MediaListRow.svelte`

### 5. Add keyboard exit behavior
On `gallery-root` in `GalleryGrid.svelte`:
- handle `Escape`
- when selection mode is active, exit selection mode and clear selection

This also helps with desktop parity before action buttons exist.

### 6. Keep accessibility changes minimal and truthful
- Do not try to solve unrelated focus architecture in the same block.
- If touching keyboard handlers reveals a cleaner fix for the existing `tabindex` warning in `GalleryGrid.svelte`, that can be included only if it remains small and does not broaden scope.
- Otherwise keep the warning tracked in status.

## Acceptance Criteria For This Block
- Touch long-press on a gallery item enters selection mode and selects the first item.
- Ctrl/Meta click toggles single-item selection on desktop.
- Shift click selects a visible range using current filtered order.
- Selection header replaces the normal gallery header while active.
- `Select All` selects the current filtered visible items.
- `Cancel` and `Escape` exit selection mode and clear selection.
- Normal click still opens viewer when selection mode is inactive.
- `npm run check` passes.
- Short suite passes.
- Mobile long-press test passes.

## Risks And Controls
- Risk: shift-range logic selects hidden/non-visible items.
  - Control: always compute ranges from `visibleItems` in `GalleryGrid.svelte`.
- Risk: long-press triggers click-open after selection starts.
  - Control: preserve existing `longPressTriggered` guard in item components.
- Risk: introducing selection state in store causes stale selection across dialog changes.
  - Control: clear selection inside `resetDialogState()`.
- Risk: adding fake action buttons implies unsupported behavior.
  - Control: keep this block to selection-only controls unless actions are actually implemented.
