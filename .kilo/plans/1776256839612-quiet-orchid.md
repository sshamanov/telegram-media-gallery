# Mock Media And Grid Controls Fix Plan

## Goal
- Restore actual mock media thumbnails and viewer previews in galleries, groups, and chats.
- Make the existing grid-columns button functional by cycling through supported column counts.
- Revalidate the repaired mock-mode UX with focused tests plus required type/test gates.

## Findings

### Mock media mismatch is the likely root cause of missing thumbnails/previews
- `src/lib/telegram/mock.ts` loads dialogs from `samples/dialogs.json`, which currently uses ids like `123456789` and `987654321`.
- The same mock adapter loads messages from `/samples/dialog-media/${dialogId}.json`.
- Those files do not exist for the ids from `samples/dialogs.json`; only `samples/dialog-media/1.json` through `5.json` and a few legacy named files exist.
- When message JSON is missing, the mock adapter falls back to synthetic messages using fallback dialogs `1..5` and filenames that may or may not align with the active dialog dataset, creating drift between visible dialogs and media payloads.
- `MediaItem.svelte` and `MediaListRow.svelte` only render actual thumbnails when `getCachedOrDownloadBlob(item, 'thumb')` returns data; otherwise they render icon-only fallbacks.
- `ViewerWrapper.svelte` similarly depends on `getCachedOrDownloadBlob()` for preview/full content, so the same mock-data problem explains empty preview behavior.

### Thumbnail loading path itself looks structurally sound
- `src/lib/files.ts` delegates thumbnail/full fetches through the adapter and caches blobs correctly.
- `src/lib/media.ts` marks photos, videos, and most document-images/videos as thumbnail-capable.
- `src/lib/thumbnails.ts` can generate thumbnails from full blobs when needed.
- Because the UI already shows fallback glyphs instead of crashing, the current failure mode is consistent with missing/empty mock media blobs rather than immediate render bugs in the components.

### Grid-columns button is currently a dead control
- In `src/components/gallery/GalleryGrid.svelte`, the `{$settings.gridColumns}x` button has no `on:click` handler.
- `src/stores/settings.ts` already persists `gridColumns`, so the missing piece is a small interaction handler.
- User preference: clicking the existing button should cycle values rather than open a picker.

## Implementation Plan

### 1. Normalize mock dialog/media datasets
- Pick one canonical mock dialog id scheme and make dialogs/messages consistent.
- Preferred approach: keep `samples/dialogs.json` as the source of truth and make `src/lib/telegram/mock.ts` resolve matching message JSON files for those ids.
- Remove or bypass the accidental fallback path during normal mock usage so galleries/groups/chats load real sample media instead of synthetic placeholders.
- Verify that each dialog in `samples/dialogs.json` maps to an existing media JSON file and that those message files reference sample binaries that exist under `samples/`.

### 2. Harden mock media file resolution
- Update mock media loading so `downloadThumbnail()` and `downloadFull()` reliably resolve sample files referenced by message payloads.
- Ensure photo/video/document sample files produce non-empty blobs in mock mode.
- Keep the icon placeholder fallback only as a true last resort when a sample file is intentionally missing or corrupt.
- Add targeted debug logging around missing sample message files / missing sample media files so visual testing issues are diagnosable without flooding logs.

### 3. Verify thumbnail and preview rendering paths against mock data
- Confirm grid cards and list rows render image/video thumbs once mock blobs are available.
- Confirm viewer preview/full rendering works for:
  - photos
  - videos
  - representative document types already claimed in Phase 1 (PDF/audio/text/document-image/document-video as applicable)
- If any remaining preview gap is due to unsupported browser rendering rather than data mismatch, document that explicitly instead of masking it.

### 4. Implement grid-columns cycling control
- Add a click handler to the existing `Grid columns` button in `src/components/gallery/GalleryGrid.svelte`.
- Cycle through a small supported set, likely desktop-oriented values such as `2 -> 3 -> 4 -> 5 -> 2`, with mobile behavior still respecting persisted settings.
- Update the tooltip/ARIA label if needed so the button communicates that it cycles values.
- Reuse `updateSettings()` from `src/stores/settings.ts` rather than adding duplicate state logic.

### 5. Add or update automated coverage
- Extend short Playwright coverage for the grid-columns button so the button click changes the displayed count and the grid layout state.
- Add a focused mock-media assertion that at least one gallery item renders an actual `<img>` thumbnail instead of only the fallback glyph, and that opening a supported media item produces visible viewer content.
- Keep tests executable-only and aligned with currently supported mock behavior.

### 6. Validate and record the logical block
- Run `npm run check` in Docker.
- Run required short-suite coverage in Docker Compose.
- Run any additional targeted viewer/gallery test if needed to protect the repaired mock-media path.
- Update `.kilo/status.md` during implementation with plan activation, todo state changes, validation results, blockers, and commit hash.
- Commit as a single logical fix block before moving to the next feature.

## Files Likely To Change During Implementation
- `src/lib/telegram/mock.ts`
- `samples/dialogs.json` and/or `samples/dialog-media/*.json`
- `src/components/gallery/GalleryGrid.svelte`
- `src/stores/settings.ts` (only if a helper is useful)
- `tests/e2e/short/gallery.spec.ts`
- possibly `tests/e2e/short/viewer.spec.ts` if viewer coverage needs a mock-media-specific assertion
- `.kilo/status.md`

## Risks And Checks
- If sample message files reference binaries that do not exist, the implementation must fix the sample map, not just hide failures with placeholders.
- Changing dialog ids or sample filenames can break existing mock-based tests, so tests should be updated in the same logical block.
- Viewer behavior differs by media type; acceptance should focus on types already claimed as supported in the spec/status.

## Acceptance Criteria
- In mock mode, chats/groups/galleries show real thumbnails for available sample media instead of icon-only placeholders.
- Opening a supported media item shows real preview/full viewer content instead of an empty-looking fallback when sample media exists.
- The `4x` grid-columns button cycles through supported counts and visibly changes the grid layout.
- Required validation passes and the fix is recorded truthfully in `.kilo/status.md`.
