## Goal
Eliminate `future-backlog.md` from the workflow, clean up legacy references, and clarify document boundaries between `APPLICATION_SPEC.md` (goal state) and `AGENTS.md` (process management).

## Status: draft

## Current State
- Backlog system established in `.kilo/future-backlog.md` with 8 items, three marked completed (FB001, FB008, FB002).
- Active plan `.kilo/plans/1776334107170-playful-moon.md` references the backlog file and includes all backlog items across its phases.
- AGENTS.md contains rule 8 restricting backlog file edits to Plan mode and a planning rule to update backlog item status.
- `.kilo/agent/hard-route.md` references the backlog file as a source for new work.
- Legacy references to `legacy-archive` branch exist in AGENTS.md, APPLICATION_SPEC.md, TECHNICAL_MIGRATION_PLAN.md, and kilo-dev-process.md.
- TECHNICAL_MIGRATION_PLAN.md is referenced in AGENTS.md and several command files (design-check.md, phase-check.md, spec.md) but its content is largely superseded by executed plans.
- kilo-dev-process.md contains MVP architecture analysis; its relevance to current development is low.
- APPLICATION_SPEC.md and AGENTS.md have overlapping sections (SYSTEM BOUNDARIES) and some process details that could be clarified.

## Success Criteria
1. Backlog file removed; no references to it remain in AGENTS.md, hard-route.md, or any other operational document.
2. Legacy‑archive branch references removed from AGENTS.md and other authoritative docs (where they are not essential for historical context).
3. TECHNICAL_MIGRATION_PLAN.md references removed from AGENTS.md and command files; the file itself archived (moved to `.kilo/archive/`).
4. kilo-dev-process.md reviewed, any still‑relevant architectural details moved to APPLICATION_SPEC.md, then file archived.
5. APPLICATION_SPEC.md and AGENTS.md have clean boundaries: APPLICATION_SPEC.md focuses on architecture and supported behavior; AGENTS.md focuses on execution workflow and agent rules. SYSTEM BOUNDARIES moved to AGENTS.md only, with a reference in APPLICATION_SPEC.md.
6. All changes pass type check and short test suite validation.
