# Status Ledger Migration Plan

## Goal
- Move the canonical execution-ledger location from `.kilo/status.md` to `STATUS.md`.
- Replace the temporary copied artifacts with the new canonical file arrangement.
- Update all authoritative workflow/rule references so future work uses `STATUS.md` instead of `.kilo/status.md`.

## Constraints
- Planning-only step; no filesystem changes are executed here.
- The final state must not keep `STATUS.md` ignored, because it becomes the tracked source-of-truth ledger.
- The old `.kilo/status.md` path should remain available only long enough to create the hard link and complete rule/config migration, then be removed.

## Scope To Update
- Canonical ledger file: `STATUS.md`
- Remove redundant copies: `.kilo/status.md.js`, pre-existing copied `STATUS.md`
- Workflow/rule authorities: `AGENTS.md`, `APPLICATION_SPEC.md`, `TESTING_STRATEGY.md`, `kilo.jsonc`
- Active plan / governance references that define current execution flow
- `.gitignore` so `STATUS.md` is no longer ignored

### Confirmed authoritative references to update
- `AGENTS.md`
  - commit flow steps that currently require updates to `.kilo/status.md`
  - document-authority and status-ledger rules sections
  - planning/execution rules
  - failure-handling rule
  - reference-files list
  - status minimum sections declaration
- `APPLICATION_SPEC.md`
  - document-authority section
  - validation/deferral workflow rules
  - development workflow required-order section
  - commit-discipline note
  - cross-references section
- `TESTING_STRATEGY.md`
  - document-role section
  - validation/deferral rules
  - current known testing gaps
  - failure-handling rule
  - agent requirements
  - references section
- `kilo.jsonc`
  - agent-specific edit permissions for `code` and `plan`
  - global edit permissions for old `.kilo/status.md` patterns
- `STATUS.md`
  - authority split text
  - self-referential todo/history/drift entries only where they are normative rather than historical
- `.gitignore`
  - remove the `STATUS.md` ignore entry

## Implementation Order
1. Remove the current copied `STATUS.md`.
2. Create a hard link from `.kilo/status.md` to `STATUS.md` so both paths point to the same inode during migration.
3. Remove `.kilo/status.md.js` because it is only a redundant copy.
4. Update authoritative docs/config/rules so `STATUS.md` is the canonical execution ledger path:
   - `AGENTS.md`
   - `APPLICATION_SPEC.md`
   - `TESTING_STRATEGY.md`
   - `kilo.jsonc`
5. Update the ledger content itself in `STATUS.md` so normative/self-referential instructions point to `STATUS.md`.
6. Remove `STATUS.md` from `.gitignore` so the new canonical ledger is tracked.
7. Re-check for remaining normative references to `.kilo/status.md`; leave purely historical references only if they are preserved as factual history rather than active rules.
8. Remove the old `.kilo/status.md` path after the migration is complete.

### Detailed execution notes
- Use the existing `.kilo/status.md` contents as the migration source of truth while the hard link exists.
- Do not rewrite dated historical facts merely to replace old path mentions inside past entries, commit descriptions, or old plans.
- Do rewrite forward-looking instructions inside `STATUS.md` itself when they are telling future readers what path to use.
- When removing `.kilo/status.md`, make sure `STATUS.md` remains as the surviving tracked file rather than deleting the shared inode accidentally.
- After the old path is removed, the active execution-ledger updates for this migration must be recorded in `STATUS.md` only.

## Reference Update Rules
- Update all active workflow/rule language to `STATUS.md`.
- Update edit-permission entries in `kilo.jsonc` from `.kilo/status.md` to `STATUS.md` (and any wildcard forms that exist only for the old path).
- Update status-ledger self-descriptions so it declares `STATUS.md` as the execution ledger.
- Preserve historical facts where appropriate (for example, old commit messages or dated ledger/history entries) unless explicitly rewriting history is desired.

## Validation Plan
1. Verify `STATUS.md` and the temporary `.kilo/status.md` hard link refer to the same inode immediately after linking.
2. Grep for `.kilo/status.md` across governance/config files and confirm remaining hits are either intentionally historical or removed.
3. Verify `.gitignore` no longer ignores `STATUS.md`.
4. Run `docker run --rm --network host -v "$(pwd)":/app -w /app node:24-alpine npm run check`.
   - Reason: the migration touches workflow/config authority (`kilo.jsonc`, `.gitignore`, governance docs) and the repo process treats `npm run check` as the default logical-block gate unless truthfully deferred.
   - No Playwright suites are required unless implementation unexpectedly changes executable product behavior.
5. Verify the old `.kilo/status.md` path no longer exists at the end.
6. Run a final grep for `STATUS.md` and `.kilo/status.md` to confirm the authoritative path flip is complete and remaining old-path hits are historical only.

## Expected End State
- `STATUS.md` is the only canonical execution ledger path.
- `.kilo/status.md.js` is removed.
- `.kilo/status.md` is removed after migration.
- `STATUS.md` is no longer ignored by git.
- All authoritative flows and rules point to `STATUS.md`.

## Notes
- The current repo contains many historical references to `.kilo/status.md` inside plans and past ledger entries. The implementation should prioritize authoritative, forward-looking workflow/rule references first, and only rewrite history where doing so improves clarity without falsifying the record.
- A prior copied `STATUS.md` already exists in the repo, so the implementation must replace that copy before linking to avoid carrying stale duplicate content forward.
- `APPLICATION_SPEC.md` and `TESTING_STRATEGY.md` still contain several old-path workflow references, so the migration is not just a file move; it is a governance-path reconciliation.
