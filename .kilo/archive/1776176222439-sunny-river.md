# Guidance Compliance And Recovery Plan

## Goal
- Verify whether the current repo state follows the required development guidance before fixing product issues.
- Produce an implementation plan that first repairs process truth (`APPLICATION_SPEC.md`, `.kilo/status.md`, `AGENTS.md`, testing docs/rules), then restores the broken product paths.
- Treat `APPLICATION_SPEC.md` as architecture/source of truth, `.kilo/status.md` as execution ledger, and make `AGENTS.md` enforce synchronization between them.

## What The Audit Shows

### Guidance is currently not being followed
- `AGENTS.md` says every commit must be a working app with no stubs, but `src/components/gallery/GalleryGrid.svelte` still contains many TODOs, placeholder toasts, and undefined symbols.
- `AGENTS.md` says no production `console.log`, but `src/App.svelte`, `src/lib/dom/keyboard-shortcuts.ts`, and `src/lib/telegram/mock.ts` still use direct `console.*`.
- `AGENTS.md` says tests must be real assertions, but several short and long Playwright specs are commented-out or placeholder-oriented rather than validating real supported UI.
- `AGENTS.md` requires disciplined status/progress tracking, but `.kilo/status.md` is stale, inaccurate, and not functioning as a live work ledger.

### Current docs contradict validated reality
- `APPLICATION_SPEC.md` still mentions a removed mock UI toggle, claims Playwright tests are not implemented, and contains environment guidance that conflicts with `AGENTS.md`.
- `.kilo/status.md` claims the app is feature-complete and all five flows work, but gallery/viewer/test coverage is currently degraded and partially stubbed.
- `TESTING_STRATEGY.md` describes ideal coverage, but not the current executable/real test scope.
- Process docs and commands are stale enough that agents can follow them and still violate current project rules.

### Main product risk to fix after process alignment
- `src/components/gallery/GalleryGrid.svelte` is the largest blocker. It has a template/script mismatch, undefined identifiers, and incomplete behaviors that break the “working app” rule and force tests to be watered down.

## Key Decisions For Implementation
- Fix product issues only; do not plan git-history cleanup or generated-artifact cleanup as part of this effort.
- Use a **baseline then rebuild** strategy for gallery work: restore a small, type-safe, working gallery first, then reintroduce advanced features in logical blocks.
- Convert `.kilo/status.md` into a **structured ledger**.
- Require status updates for **every plan, every todo state transition, every logical block, and every commit**.
- Make long tests **executable only**; remove or rewrite placeholder/speculative expectations.
- Correct `APPLICATION_SPEC.md` fully so it matches real architecture, validated behavior, and currently accepted gaps.

## Required Document Roles

### `APPLICATION_SPEC.md`
- Source of truth for intended architecture, supported user flows, supported test contract, environment rules, and known accepted limitations.
- Must clearly distinguish:
  - supported/current behavior
  - planned-but-not-yet-restored behavior
  - test expectations that are currently required gates

### `.kilo/status.md`
- Execution ledger for what is actively happening now.
- Must track at minimum:
  - active plan
  - current phase
  - current todo list with states (`pending`, `in_progress`, `failed`, `completed`)
  - current blockers / contradictions
  - last validation results (`npm run check`, short tests, long tests if applicable)
  - recent commits and what each completed
  - spec/status drift notes if any remain open

### `AGENTS.md`
- Must explicitly require agents to:
  - read `APPLICATION_SPEC.md` and `.kilo/status.md` before implementation
  - create/update a plan before non-trivial work
  - write every todo state transition into `.kilo/status.md`
  - record validation outcomes in `.kilo/status.md`
  - record each logical block and each commit in `.kilo/status.md`
  - update `APPLICATION_SPEC.md` when architecture, flow, or supported behavior changes
  - never claim a flow is complete in status unless backed by passing checks/tests

## Implementation Plan

### Phase 1 - Re-establish process truth first
1. Rewrite `.kilo/status.md` into a structured operational ledger.
2. Update `AGENTS.md` so status tracking is mandatory at:
   - plan creation
   - todo creation/change
   - validation runs
   - logical block completion
   - commit completion
3. Update `APPLICATION_SPEC.md` to remove stale claims and align with validated repo reality.
4. Update `TESTING_STRATEGY.md` so it describes real executable suites, real selectors/contracts, and no placeholders.
5. Review stale Kilo workflow docs/commands (`.kilo/command/*.md`, `.kilo/agent/*.md`) and align them with the enforced process.

### Phase 2 - Restore build and type safety baseline
1. Fix `src/components/gallery/GalleryGrid.svelte` by reducing it to a smaller working baseline:
   - compile cleanly
   - support route entry and rendering
   - support visible media list/grid
   - support opening viewer
   - support filter bar and view toggle at baseline
2. Remove or defer broken advanced controls until they are reintroduced in later logical blocks.
3. Replace direct `console.*` in touched production code with `src/lib/debug.ts` usage or remove debug output.
4. Fix obvious strict-TypeScript violations in the touched path that block `npm run check`.

### Phase 3 - Restore trustworthy short tests
1. Replace commented/empty short specs with real executable assertions.
2. Align selectors and expectations with actual durable hooks already in the UI.
3. Ensure short suite covers only supported current behavior:
   - auth
   - dialogs
   - gallery baseline
   - viewer baseline
   - settings baseline
4. Remove “skip for now” style dead assertions from required suites.

### Phase 4 - Repair long tests so they are executable only
1. Audit each long spec against actual supported UI.
2. Rewrite/remove speculative expectations such as:
   - non-existent confirmation dialogs for cache clearing
   - non-existent menu/hamburger UI on mobile
   - upload/download/share flows that are not yet truly supported in the current baseline
3. Keep long tests limited to flows that are both implemented and stable.
4. Mark advanced gallery capabilities as future logical blocks in status/spec rather than pretending coverage exists.

### Phase 5 - Reintroduce advanced gallery features in logical blocks
1. Infinite scroll / sentinel wiring.
2. Scroll restoration.
3. Selection mode derived state and bulk actions.
4. Upload baseline if truly supported.
5. Download/share/copy/forward only when each is implemented end-to-end.
6. Keyboard navigation and onboarding only when fully wired and testable.
7. Masonry behavior only after baseline grid/list is stable and typed.

For each block:
- update status todo entries
- update spec if supported behavior changes
- run validations required by `AGENTS.md`
- commit separately

## Validation Gates During Implementation
- After process-doc updates: run short tests if selectors/contracts changed; otherwise at least `npm run check` once implementation starts.
- After gallery baseline rebuild: run `npm run check` and short tests.
- After short-test repair: run short tests end-to-end.
- After any long-test changes touching supported long flows: run the relevant long subset.
- Do not mark a flow complete in status/spec until the required validation has passed.

## Risks And Controls
- Risk: rewriting docs before code may still leave drift.
  - Control: docs first establish truthful current state, not aspirational state.
- Risk: trying to fix current gallery in place will preserve hidden breakage.
  - Control: baseline-first rebuild with smaller supported scope.
- Risk: tests can be made green by weakening assertions too far.
  - Control: required suites must use executable assertions for only real supported behavior; unsupported behavior must be removed from required claims, not hidden.
- Risk: status will become stale again.
  - Control: enforce ledger updates in `AGENTS.md` and in the spec/process docs.

## Acceptance Criteria
- `APPLICATION_SPEC.md`, `.kilo/status.md`, and `AGENTS.md` no longer contradict each other on current architecture, workflow, and supported behavior.
- `.kilo/status.md` is a structured live ledger that tracks plans, todo states, validations, blockers, and commits.
- `AGENTS.md` explicitly requires agents to track everything in `.kilo/status.md`.
- `GalleryGrid.svelte` is restored to a type-safe working baseline with no undefined identifiers in the supported baseline path.
- Required short tests are real executable assertions with no commented-out placeholders.
- Long tests cover only executable supported flows.
- The app can be described truthfully in status/spec without overstating completion.

## Recommended Execution Order
1. Rewrite status ledger structure.
2. Tighten AGENTS process rules around status/spec sync.
3. Correct `APPLICATION_SPEC.md` and `TESTING_STRATEGY.md` to truthful current state.
4. Rebuild gallery baseline until `npm run check` can pass for touched paths and the app flow is real.
5. Replace empty/placeholder short specs with real assertions.
6. Prune or rewrite long specs to executable-only coverage.
7. Reintroduce advanced gallery features one logical block at a time with status/spec/test updates each time.
